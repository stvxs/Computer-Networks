# 6. Расчет подсетей и планирование адресного пространства - HW Cisco

## Задание

В Cisco Packet Tracer необходимо построить локальную сеть, состоящую из 8 компьютеров, 2 коммутаторов и 1 хаба.

Для выполнения домашнего задания необходимо:
- Построить схему сети в Cisco Packet Tracer.
- Настроить IP-адреса компьютеров и маску подсети.
- Проверить соединение между компьютерами с помощью команды `ping` в консоли.
- Продемонстрировать отправку ping в режиме Simulation.

## 1. Построение сети

В Cisco была создана локальная сеть, состоящая из следующих устройств:

- 8 компьютеров (PC0-PC7);
- 2 коммутаторов (Switch0 и Switch1);
- 1 хаба (Hub0).

PC0-PC3 подключены к Switch0. PC4 и PC5 подключены к Switch1. Коммутаторы соединены между собой. Hub0 подключён к Switch1, а PC6 и PC7 подключены к хабу.

## 2. Расчет адресного пространства

Для сети была выбрана подсеть `192.168.10.0/28`.

**Маска подсети:** `255.255.255.240`.

Префикс `/28` означает, что 28 бит используются для идентификации сети, а оставшиеся 4 бита - для адресации узлов.

Количество адресов рассчитывается по формуле:

`2^(32 - 28) = 2^4 = 16`

Из общего количества адресов два зарезервированы:
- Один адрес для обозначения сети.
- Один адрес для широковещательной рассылки (broadcast).

Количество доступных адресов узлов:

`16 - 2 = 14`

| Параметр | Значение |
|---|---|
| Адрес сети | `192.168.10.0` |
| Маска подсети | `255.255.255.240` |
| Префикс | `/28` |
| Первый доступный адрес | `192.168.10.1` |
| Последний доступный адрес | `192.168.10.14` |
| Широковещательный адрес | `192.168.10.15` |
| Количество доступных адресов | 14 |

## 3. План IP-адресации

Каждому компьютеру назначается уникальный IP-адрес из диапазона доступных адресов подсети.

| Устройство | IP-адрес | Маска подсети |
|---|---|---|
| PC0 | `192.168.10.1` | `255.255.255.240` |
| PC1 | `192.168.10.2` | `255.255.255.240` |
| PC2 | `192.168.10.3` | `255.255.255.240` |
| PC3 | `192.168.10.4` | `255.255.255.240` |
| PC4 | `192.168.10.5` | `255.255.255.240` |
| PC5 | `192.168.10.6` | `255.255.255.240` |
| PC6 | `192.168.10.7` | `255.255.255.240` |
| PC7 | `192.168.10.8` | `255.255.255.240` |

Шлюз по умолчанию не указывается, так как в данной топологии отсутствует маршрутизатор.

## 4. Проверка связи между компьютерами

Для проверки соединения с PC0 на PC7 была выполнена команда:

`ping 192.168.10.8`

В результате получены ответы от компьютера с адресом `192.168.10.8`. Потерь пакетов не было.

## 5. Передача пакетов в режиме Simulation

Для проверки передачи данных был использован режим Simulation в Cisco Packet Tracer.

С помощью инструмента Add Simple PDU был отправлен тестовый пакет от PC0 к PC7.

Пакет прошёл через следующие устройства:

`PC0 -> Switch0 -> Switch1 -> Hub0 -> PC7`

После получения пакета компьютером PC7 ответ прошёл в обратном направлении.
