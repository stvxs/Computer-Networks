## 2. Построение и настройка сети в Cisco Packet Tracer

### Условие задания

Вам потребуется распределить 127.168 /24 IP адрес на подсети где 5 зданий с маршрутами и в каждом от 15 до 25 устройств.

### Построение сети

В топологии созданы:

- 5 маршрутизаторов Cisco 2911;
- 5 коммутаторов Cisco 2960;
- 5 компьютеров - по одному тестовому компьютеру в каждом здании;
- соединения между компьютерами, коммутаторами и маршрутизаторами;
- соединения между маршрутизаторами для передачи данных между зданиями.

Маршрутизаторы соединены последовательно. Каждый маршрутизатор подключён к локальной сети своего здания через коммутатор.

<img width="500" height="400" alt="image" src="https://github.com/user-attachments/assets/560e524a-2f9b-4e70-81ce-466e1539a03b" />

### Выбор IP-адресации и проверка исходного адреса

В задании указан адрес 127.168 /24. Сначала была попытка использовать адрес 127.168.0.0/24.

После ввода программа вывела сообщение об ошибке: “This is an invalid IP address” («Недопустимый IP-адрес»).

<img width="271" height="125" alt="image" src="https://github.com/user-attachments/assets/137bf394-f9fc-4af1-84e6-f79f79197c43" />

Диапазон 127.0.0.0/8 зарезервирован для loopback - тестирования сетевых функций самого компьютера. Он не предназначен для построения обычной маршрутизируемой сети между несколькими зданиями.

После возникновения ошибки для построения рабочей модели была выбрана сеть 192.168.0.0/24. На ней были настроены подсети пяти зданий, соединения между маршрутизаторами и статические маршруты.

### 2.1. Распределение IP-адресов между зданиями

Для локальных сетей зданий использована маска `/27` - `255.255.255.224`.

Подсеть `/27` содержит 32 IP-адреса, из которых 30 можно назначить устройствам. Этого достаточно для здания с 15-25 устройствами.

| Здание | Адрес сети | IP маршрутизатора | IP компьютера | Шлюз компьютера |
|---|---|---|---|---|
| 1 | `192.168.0.0/27` | `192.168.0.1` | `192.168.0.2` | `192.168.0.1` |
| 2 | `192.168.0.32/27` | `192.168.0.33` | `192.168.0.34` | `192.168.0.33` |
| 3 | `192.168.0.64/27` | `192.168.0.65` | `192.168.0.66` | `192.168.0.65` |
| 4 | `192.168.0.96/27` | `192.168.0.97` | `192.168.0.98` | `192.168.0.97` |
| 5 | `192.168.0.128/27` | `192.168.0.129` | `192.168.0.130` | `192.168.0.129` |

#### Почему в каждом здании размещён только один компьютер

В каждой локальной сети оставлен один тестовый компьютер. Добавлять ещё по 14 компьютеров в каждое здание для проверки основной работоспособности маршрутизации необязательно: связь между сетями определяется настройками IP-адресации, шлюзов и маршрутов на маршрутизаторах, а не количеством компьютеров на схеме.

Маска `/27` предоставляет 30 пригодных IPv4-адресов для устройств в каждой подсети. Этого достаточно для адресации 15-25 устройств в здании.

### 2.2. Адресация соединений между маршрутизаторами

Для соединений между маршрутизаторами использована маска `/30` - `255.255.255.252`.

Подсеть `/30` содержит четыре адреса: адрес сети, два пригодных адреса устройств и широковещательный адрес. Поэтому она подходит для соединения двух маршрутизаторов.

| Соединение | Адрес сети | IP первого маршрутизатора | IP второго маршрутизатора |
|---|---|---|---|
| Router0 - Router1 | `192.168.0.160/30` | R0: `192.168.0.161` | R1: `192.168.0.162` |
| Router1 - Router2 | `192.168.0.164/30` | R1: `192.168.0.165` | R2: `192.168.0.166` |
| Router2 - Router3 | `192.168.0.168/30` | R2: `192.168.0.169` | R3: `192.168.0.170` |
| Router3 - Router4 | `192.168.0.172/30` | R3: `192.168.0.173` | R4: `192.168.0.174` |

Каждый маршрутизатор имеет интерфейс для локальной сети своего здания и интерфейсы для связи с соседними маршрутизаторами.

### 2.3. Настройка маршрутизации

Для обмена данными между зданиями настроены статические маршруты.

Статический маршрут указывает маршрутизатору, куда передавать пакет, если сеть назначения не подключена к нему напрямую.

При настройке статического маршрута используются:

- **Network** - адрес сети назначения;
- **Mask** - маска сети назначения;
- **Next Hop** - IP-адрес следующего маршрутизатора, которому нужно передать пакет.

Маршруты настроены следующим образом:

| Маршрутизатор | Сети, доступные через статические маршруты |
|---|---|
| Router0 | `192.168.0.32/27`, `192.168.0.64/27`, `192.168.0.96/27`, `192.168.0.128/27` через `192.168.0.162` |
| Router1 | `192.168.0.0/27` через `192.168.0.161`; `192.168.0.64/27`, `192.168.0.96/27`, `192.168.0.128/27` через `192.168.0.166` |
| Router2 | `192.168.0.0/27`, `192.168.0.32/27` через `192.168.0.165`; `192.168.0.96/27`, `192.168.0.128/27` через `192.168.0.170` |
| Router3 | `192.168.0.0/27`, `192.168.0.32/27`, `192.168.0.64/27` через `192.168.0.169`; `192.168.0.128/27` через `192.168.0.174` |
| Router4 | `192.168.0.0/27`, `192.168.0.32/27`, `192.168.0.64/27`, `192.168.0.96/27` через `192.168.0.173` |

Сеть, непосредственно подключённая к интерфейсу маршрутизатора, обычно не требует отдельного статического маршрута на этом же маршрутизаторе.

### 2.4. Проверка работоспособности сети с помощью ping

Для проверки использована команда `ping`. Она отправляет тестовые ICMP-пакеты на указанный IP-адрес и показывает, отвечает ли устройство.

#### Проверка связи из первого здания в пятое

На компьютере PC0 выполнена команда:

```text
ping 192.168.0.130
```

Адрес `192.168.0.130` принадлежит компьютеру PC4 в пятом здании.

В результате получены четыре ответа. Потерь пакетов не было - 0% loss.

Это показывает, что тестовые пакеты прошли от первого компьютера через маршрутизаторы к компьютеру в пятом здании, а ответы вернулись обратно.

## 3. Расчёт длины маски подсети

**Условие:** найти нужную длину маски для 20 подсетей и 10 узлов.

### 3.1. Расчёт количества бит для подсетей

Для определения количества бит используем степени двойки:

- 2⁴ = 16 - недостаточно для 20 подсетей.
- 2⁵ = 32 - достаточно.

Следовательно, для подсетей необходимо **5 бит**.

### 3.2. Расчёт количества бит для узлов

Для определения количества доступных адресов узлов используем формулу:

**Количество узлов = 2ʰ − 2**, где `h` - количество бит для узлов. Вычитаем 2, так как один адрес используется для обозначения сети, а второй - для широковещательной рассылки.

- 2³ − 2 = 6 - недостаточно для 10 узлов.
- 2⁴ − 2 = 14 - достаточно.

Следовательно, для узлов необходимо **4 бита**.

### 3.3. Определение итоговой маски

Для подсетей требуется 5 бит, а для узлов - 4 бита. Всего необходимо:

5 + 4 = 9 бит.

Исходная сеть `/24`: итоговая маска `/29`. Остаётся 3 бита для узлов: 2³ − 2 = 6 адресов - недостаточно.

Исходная сеть `/23`: итоговая маска `/28`. Остаётся 4 бита для узлов: 2⁴ − 2 = 14 адресов - достаточно.

### Ответ

Точную итоговую маску нельзя определить без исходного префикса сети. Например, при исходной сети `/23` подходит маска `/28` (`255.255.255.240`), которая обеспечивает 32 подсети и 14 доступных адресов узлов в каждой.
